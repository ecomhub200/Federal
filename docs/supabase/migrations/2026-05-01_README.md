# 2026-05-01 — Tier-aware road buckets, map RPC parity, perf

These migrations implement the database half of the
"Crash Lens — Supabase-First, Tier-Aware Road Types, Map Parity &
Performance" prompt (2026-05-01). The JS half lands in a follow-up
commit on the same branch (`claude/crash-lens-supabase-maps-WS15L`)
**after** these migrations are applied and verified.

## Why a separate run

The JS edits assume the DB exposes:

- a `city_roads` value in `road_type` on every detail matview
- an `is_interstate` boolean on every detail matview
- `p_road_type`, `p_road_types`, `p_no_interstate` parameters on
  `map_viewport_crashes`

If the JS ships before the DB migrates, the new "City Roads Only" and
"All Roads (No Interstate)" radios will return empty results. **Apply
the migrations first, post the §10 verification output back to the
ticket, then merge the JS PR.**

## How to apply

Each step `01`–`09` is wrapped to be safe with Supabase MCP
`apply_migration` (idempotent `DROP … IF EXISTS` + `CREATE`).
Step `00` and step `10` are read-only and should run via
`execute_sql`.

```text
# Pseudocode for the backend agent / engineer with DB access
execute_sql(file="2026-05-01_00_reality_check.sql")  → save output to ticket
```

## Special steps

### Step 7 — `map_viewport_crashes` is a TEMPLATE

The prompt (§7.7) requires preserving the current RPC body and only
splicing the new `WHERE` fragments + new parameters. We don't have the
current body in git, so:

1. **Capture the existing definition first.** Run this via
   `execute_sql` and save the result verbatim to
   `docs/rollback/map_viewport_crashes.pre.sql` (the placeholder is
   already committed):
   ```sql
   SELECT pg_get_functiondef(
     'public.map_viewport_crashes(text,geometry,integer,text,text,integer,text[],integer)'::regprocedure
   );
   ```
2. Open `2026-05-01_07_map_viewport_crashes_TEMPLATE.sql`. It contains:
   - the new function signature (3 new params before `p_limit`)
   - clearly-marked splice points (`-- ⬇ NEW WHERE FRAGMENT ⬇`)
   - the exact SQL fragments to inject into every CTE / subquery that
     reads `crashes`
3. Paste the captured body into the marked region, splice in the
   fragments, and `apply_migration` the result.

If the captured body is short enough to ship in this commit, replace
the TEMPLATE file in this PR with the spliced version and re-run.
Otherwise leave the template + a note in the ticket.

### `pg_cron` and `pg_prewarm`

Step 9 assumes both extensions are installed. If `pg_cron` is not
available on the self-hosted instance, drop the `cron.schedule(...)`
line and wire the refresh procedure into your existing scheduler.
`pg_prewarm` is a contrib module; if it's missing, the `CREATE
EXTENSION IF NOT EXISTS pg_prewarm;` will surface a clean error and
you can comment those lines out.

### PostgREST env

Step 8 ships only the SQL function. To activate it, set
`PGRST_DB_PRE_REQUEST=public.add_cache_headers` in the PostgREST
container env and reload PostgREST. (Outside the scope of `apply_migration`.)
