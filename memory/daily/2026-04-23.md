# Daily Log: 2026-04-23

## Sessions

### Phase 4 rollout & R2 parquet policy

Shipped Phase 4 (server-paginated Dashboard/Analysis search + CMF/Warrants
via Supabase) on branch `claude/read-phase4-docs-I44zm`. During live
browser testing on Delaware/Sussex the console returned two actionable
signals:

1. A compound Phase 4 query (`text + multi-severity + pedBike=either`) hit
   Supabase statement timeout — `500 Internal Server Error — canceling
   statement due to statement timeout`. The ILIKE full-scan across 5 columns
   on 86K Sussex rows is the culprit. Not a client bug; future work needs
   GIN/trigram indexes or query simplification.
2. When Supabase errored, the R2 fallback in
   `assets/js/data-client.js:_r2LoadCrashes()` tried
   `delaware/sussex/all_roads.csv` and 404'd because the bucket only has
   `.parquet` (and legacy `.parquet.gz`). The CSV fallback is a relic from
   Phase 1.

### Decision

From 2026-04-23 forward, R2 crash data is **`.parquet` only** — no
`.parquet.gz`, no `.csv`, no `.csv.gz`. See
[[concepts/r2-parquet-policy]] for the full policy.

Fixed `_r2LoadCrashes()`:
- Drop the CSV fallback entirely.
- Fetch the `.parquet` URL directly and hand the bytes to the app's
  shared `_parseParquetGz()` (which already tolerates raw parquet via
  gzip-magic-byte sniffing).
- Keep a standalone hyparquet import path for Node/test environments.

All 55 assertions in `tests/test_phase4_data_client.js` still pass.
